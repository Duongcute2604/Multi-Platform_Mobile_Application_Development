PHẦN A - CÂU HỎI LÝ THUYẾT

Câu 1. Vai trò của StyleSheet và vì sao ưu tiên StyleSheet.create()

StyleSheet là API chuẩn của React Native dùng để khai báo và quản lý các style (đối tượng style) thay vì viết trực tiếp inline trong JSX. StyleSheet có các vai trò sau:

  • Tách bạch cấu trúc và trang trí: JSX mô tả cấu trúc giao diện, styles mô tả hình thức; style được khai báo tập trung ở cuối file nên code gọn gàng, dễ đọc, dễ sửa.
  • Tăng hiệu năng: StyleSheet.create() trả về object bất biến và React Native ánh xạ mỗi style thành một ID. Khi render, style được tham chiếu theo ID chứ không tạo một object mới mỗi lần render. Nhờ đó giảm số object rác, giảm thời gian so sánh và re-render - đặc biệt quan trọng với danh sách dài (FlatList, ScrollView).
  • Kiểm tra lỗi sớm: ở chế độ development, StyleSheet.create() kiểm tra kiểu và giá trị của từng thuộc tính (ví dụ truyền chuỗi vào fontSize, giá trị màu sai) và cảnh báo ngay khi chạy.
  • Dễ tái sử dụng và tổ chức: style có thể export/import giữa các file và được gộp (flatten) lại một cách có trật tự.

Vì sao trong dự án thực tế nên ưu tiên StyleSheet.create() thay vì inline style:

  • Hiệu năng: inline style tạo một object mới mỗi lần render, làm component con re-render và phải gửi lại dữ liệu style; StyleSheet tránh được việc này nhờ tham chiếu ID.
  • Dễ bảo trì: style nằm tách khỏi JSX, sửa một chỗ là cả màn hình đổi; tránh lặp code style ở nhiều nơi.
  • Nhất quán (thiết kế đồng bộ): dự án dùng chung một bộ màu, khoảng cách, cỡ chữ - thay đổi tập trung, giao diện nhất quán.
  • Dễ gỡ lỗi: lỗi style chỉ ra đúng tên biến style trong file styles thay vì phải lục trong đoạn JSX dài.

Vẫn có thể dùng style inline cho vài trường hợp động (giá trị tính theo state/props), nhưng chỉ nên viết phần thay đổi trong một mảng style, ví dụ: style={[styles.button, isActive && styles.active]}.

Câu 2. Prop style và thứ tự ưu tiên khi truyền mảng style

Trong React Native, prop style có thể nhận: một object style trực tiếp, một style đã tạo từ StyleSheet.create(), hoặc mảng nhiều style.

Khi truyền một mảng nhiều style, React Native sẽ gộp (flatten) từ trái sang phải theo nguyên tắc:

  • Thuộc tính cùng tên ở phần tử sau sẽ ghi đè (override) phần tử trước.
  • Thuộc tính nào chỉ có ở phần tử sau thì được bổ sung thêm; thuộc tính chỉ có ở phần tử trước vẫn được giữ.
// styles.box: nền xám; styles.boxActive: nền xanh, viền xanh
<View style={[styles.box, styles.boxActive]}>   // nền xanh thắng (phần tử sau ghi đè)
<View style={[styles.button, disabled && styles.disabled]}>   // style có điều kiện
<View style={[styles.box, { backgroundColor: props.color }]}>  // value động ghi đè cuối

Như vậy, thứ tự rất quan trọng: phần tử đứng sau luôn có quyền quyết định cuối cùng đối với thuộc tính bị trùng. Đây cũng là cách component con nhận style từ component cha: style={[styles.default, style]} để style của cha nằm sau và ghi đè style mặc định.

Câu 3. Export, import StyleSheet và khi nào tách style ra file riêng

Sau khi khai báo const styles = StyleSheet.create({...}), ta export nó để file khác dùng lại, rồi import về khi cần:

// theme.js
export const colors = { primary: '#2563EB', background: '#F1F5F9' };
export default styles;          // export mặc định

// LoginScreen.js
import styles from './LoginScreen.styles';       // import mặc định
import { colors } from '../theme';               // import có tên

Có hai cách: export mặc định (mỗi file một styles chính, import không cần ngoặc) và export có tên (một file export nhiều nhóm: colors, spacing, styles...). Một file cũng có thể export nhiều biến style dùng chung.

Nên tách style ra file riêng khi:

  • Style dùng lại ở nhiều component hoặc nhiều màn hình (card, ô nhập, nút bấm dùng chung) - tách một lần, dùng nhiều nơi.
  • Cần một theme chung (màu, khoảng cách, bo góc, cỡ chữ) - sửa một file là cả ứng dụng đồng bộ theo.
  • File component quá dài (trăm vài dòng trở lên) - tách styles ra để code ngắn gọn, dễ đọc, dễ review.
  • Nhiều người cùng phát triển - cần một nguồn style duy nhất để giao diện nhất quán, tránh mỗi người một kiểu.

Không cần tách khi style rất ngắn, chỉ dùng cho đúng một màn hình duy nhất - khi đó để trong file component cho dễ theo dõi.

Câu 4. Truyền style qua props cho component con

Component con có thể nhận style từ component cha thông qua props rồi gộp vào style mặc định của mình. Pattern chuẩn là để style mặc định đứng trước, style truyền vào đứng sau để ghi đè:

// Button.js - nút bấm dùng chung
function Button({ title, onPress, style, textStyle }) {
  return (
    <TouchableOpacity style={[styles.button, style]}>
      <Text style={[styles.text, textStyle]}>{title}</Text>
    </TouchableOpacity>
  );
}

// Component cha dùng lại nút ở nhiều nơi, mỗi nơi một kiểu:
<Button title="Đăng nhập" style={styles.loginButton} />
<Button title="Hủy" style={styles.cancelButton} textStyle={{ fontSize: 14 }} />

Việc cho phép truyền style và textStyle giúp component linh hoạt hơn vì:

  • Một component duy nhất được dùng lại ở nhiều màn hình với màu, kích thước, khoảng cách khác nhau.
  • Không phải sửa component con hay nhân bản code cho từng biến thể nút.
  • Phần style mặc định giữ sự nhất quán, component cha chỉ ghi đè vài thuộc tính cần thiết.
  • Kết hợp với các props khác (variant, disabled, onPress...) nên một component có thể đáp ứng nhiều trường hợp dùng khác nhau.

Lưu ý: style truyền vào nằm cuối mảng nên luôn ghi đè được; nên chỉ cho phép component cha chỉnh phần trình bày, còn hành vi (bấm, tắt/mở) truyền bằng props riêng.

Câu 5. Vai trò của Flexbox và các thuộc tính quan trọng

Flexbox là mô hình layout mặc định của React Native, giúp sắp xếp các phần tử theo hàng hoặc cột và tự co giãn theo kích thước màn hình - rất thích hợp cho giao diện chạy trên nhiều kích thước màn hình khác nhau.

Lưu ý: trên web mặc định là hàng ngang (row), còn React Native mặc định là đứng dọc (column).

Thuộc tínhÝ nghĩa
flexDirectionĐịnh hướng phân bổ của container: 'column' (mặc định, xếp dọc), 'row' (xếp ngang), 'row-reverse', 'column-reverse'.
justifyContentPhân bổ khoảng trống theo trục chính (main axis): 'flex-start', 'center', 'flex-end', 'space-between', 'space-around', 'space-evenly'. Với column thì tác động theo chiều dọc.
alignItemsCăn các phần tử theo trục ngang (cross axis): 'stretch' (mặc định, kéo giãn theo trục ngang), 'center', 'flex-start', 'flex-end'.
flexChỉ định tỉ lệ chiếm không gian còn lại của phần tử. flex: 1 nghĩa là chiếm đều phần còn lại; dùng để chia màn hình thành nhiều cột (vd: cột trái 1, cột phải 2) hay để card co giãn đều nhau.
flexWrap'nowrap' (mặc định - không xuống dòng) hoặc 'wrap' - đủ chỗ thì nằm ngang, hết chỗ thì tự xuống dòng. Đây là chìa khóa làm layout responsive: 2 cột trên máy tính bảng, 1 cột trên điện thoại.

Áp dụng cho nhiều kích thước màn hình: kết hợp flexWrap: 'wrap' + flexBasis (kích thước tối thiểu) + flexGrow (mở rộng) + maxWidth (giới hạn chiều rộng), đồng thời dùng useWindowDimensions() để đọc chiều rộng màn hình thực tế rồi đổi layout cho phù hợp. Ngoài ra, vì React Native không tự cuộn phần tử tràn (không có overflow như web) nên màn hình dài cần bọc trong ScrollView.

import React, { useState } from 'react';
import {
  Platform,
  SafeAreaView,
  StatusBar,
  StyleSheet,
  Text,
  TouchableOpacity,
  View,
} from 'react-native';

import LoginScreen from './src/screens/LoginScreen';
import ProfileSettingsScreen from './src/screens/ProfileSettingsScreen';
import { colors } from './src/theme';

export default function App() {
  const [screen, setScreen] = useState('login');

  return (
    <SafeAreaView style={styles.root}>
      <StatusBar barStyle="dark-content" backgroundColor={colors.background} />

      {screen === 'login' ? <LoginScreen /> : <ProfileSettingsScreen />}

      {/* Thanh chuyển màn hình phục vụ demo - có thể xoá khi nộp bài */}
      <View style={styles.switcher}>
        <TouchableOpacity
          style={[styles.pill, screen === 'login' && styles.pillActive]}
          activeOpacity={0.8}
          onPress={() => setScreen('login')}
        >
          <Text style={[styles.pillText, screen === 'login' && styles.pillTextActive]}>
            Bài 1 - Login
          </Text>
        </TouchableOpacity>
        <TouchableOpacity
          style={[styles.pill, screen === 'profile' && styles.pillActive]}
          activeOpacity={0.8}
          onPress={() => setScreen('profile')}
        >
          <Text style={[styles.pillText, screen === 'profile' && styles.pillTextActive]}>
            Bài 2 - Profile + Settings
          </Text>
        </TouchableOpacity>
      </View>
    </SafeAreaView>
  );
}

    backgroundColor: colors.text,
    borderColor: colors.text,
  },
  pillText: {
    fontSize: 12,
    fontWeight: '600',
    color: colors.textMuted,

Bài 2 - Profile card + Settings list (mức trung bình)

Yêu cầu: dựng lại một UI đơn giản gồm thẻ hồ sơ (Profile card) và danh sách cài đặt (Settings list); dùng StyleSheet (không inline quá nhiều); layout Flexbox chuẩn; responsive - vẫn đẹp khi đổi kích thước màn hình.

Cách làm responsive:

  • Dùng useWindowDimensions() để đọc chiều rộng màn hình thực tế của thiết bị/giả lập.
  • Màn hình hẹp (< 700px - điện thoại): hai thẻ xếp dọc, mỗi thẻ chiếm 100% chiều rộng (columnFull).
  • Màn hình rộng (>= 700px - máy tính bảng, máy tính): container chuyển sang flexDirection: 'row' + flexWrap: 'wrap', mỗi thẻ có flexBasis: 300 + flexGrow: 1 nên hai thẻ nằm ngang và chia đều chiều rộng.
  • Khung nội dung giới hạn maxWidth: 960 và căn giữa để chữ không bị giãn quá trên màn hình lớn; bọc ngoài bằng ScrollView để cuộn được khi nội dung dài.
  • Flexbox thể hiện rõ: hàng 3 chỉ số trong Profile card dùng flexDirection: 'row' + mỗi ô flex: 1; dòng cài đặt dùng flexDirection: 'row' + tiêu đề flex: 1 để đẩy giá trị/mũi tên sang phải.

import React from 'react';
import { ScrollView, StyleSheet, Text, useWindowDimensions, View } from 'react-native';

import ProfileCard from '../components/ProfileCard';
import SettingsList from '../components/SettingsList';
import { colors, spacing } from '../theme';

// Từ 700px trở lên (máy tính bảng, máy tính) 2 thẻ nằm ngang, dưới đó xếp dọc.
const WIDE_MIN_WIDTH = 700;

export default function ProfileSettingsScreen() {
  const { width } = useWindowDimensions(); // đọc chiều rộng màn hình thực tế
  const isWide = width >= WIDE_MIN_WIDTH;
  const columnStyle = isWide ? styles.columnWide : styles.columnFull;

  return (
    <ScrollView style={styles.screen} contentContainerStyle={styles.content}>
      <Text style={styles.pageTitle}>Hồ sơ &amp; Cài đặt</Text>

      <View style={[styles.layout, isWide && styles.layoutWide]}>
        <ProfileCard style={columnStyle} />
        <SettingsList style={columnStyle} />
      </View>
    </ScrollView>
  );
}

const styles = StyleSheet.create({
  screen: {
    flex: 1,
    backgroundColor: colors.background,
  },
  content: {
    width: '100%',
    maxWidth: 960, // giới hạn chiều rộng để chữ không bị giãn quá trên màn hình lớn
    alignSelf: 'center',
    padding: spacing.md,
    paddingBottom: 96, // chừa chỗ cho thanh chuyển màn hình
  },
  pageTitle: {
    fontSize: 22,
    fontWeight: '700',
    color: colors.text,
    marginBottom: spacing.md,
  },
  layout: {
    gap: spacing.md, // khoảng cách giữa 2 thẻ
  },
  layoutWide: {
    flexDirection: 'row',
    flexWrap: 'wrap', // đủ chỗ thì nằm ngang, hết chỗ thì tự xuống dòng
    alignItems: 'flex-start',
    gap: spacing.lg,
  },
  columnFull: {
    width: '100%', // màn hình hẹp: chiếm hết chiều rộng, xếp dọc
  },
  columnWide: {
    flexGrow: 1,
    flexShrink: 1,
    flexBasis: 300, // màn hình rộng: mỗi thẻ tối thiểu 300px rồi co giãn đều nhau

Các bước chạy:

  1. Cài Node.js (nếu chưa có), rồi chạy npm install trong thư mục dự án.
  2. Chạy npx expo start, bấm a để mở trên giả lập Android, i cho iOS, wb cho trình duyệt.
  3. Ứng dụng mở ở màn hình Login (Bài 1); bấm nút "Bài 2 - Profile + Settings" ở góc dưới để sang màn hình thứ hai. Thanh này chỉ phục vụ demo, có thể xoá khi nộp bài.
  4. Đổi kích thước cửa sổ giả lập (hoặc xoay ngang máy tính bảng) để kiểm tra tính responsive của Bài 2.
